## 1. 挂起项 A：经验存储（参考 Hermes Experience Storage）+ HDGP 审计锁

**结论（已达成共识）**：不追求「对话记忆型聊天机器人」；追求 **动作确定、逻辑透明、可自动蒸馏生产力模板** 的工业基座。

**方向**：

- 以 **G0 动作报告**、统一审计 envelope、工作流收尾为输入，做 **经验条目 / 模板资产** 的蒸馏与版本化。
- **Markdown** 可作为展示与人工编辑面；底层必须有 **结构化 schema**（否则无法审计、检索、升级）。
- **SQLite（或等价本地存储）** 可作为 Dev/基座单机实现；须配套迁移、导出包、TTL/脱敏策略。
- **HDGP 审计锁**：写入须可证明来自 G0/审计链（correlation、hash、who/why/what/result）；**未审计资产不得默认下沉 B/C**。
- **Ranker / Hard-Anchor**：HDGP 与三公理属于 **硬闸门（fail-closed）**，排序与权重只能在合规集合内运作，不能替代伦理否决。
- **自进化技能包**：必须带 **Version_Tag**；同步至 B/C 前预留 **人工 / HDGP 审计接口**。

**与当前代码锚点**：`runG0Action`、`G0ActionReportV1`、`UnifiedAuditEventV1`、`unifiedAuditRingLog`（后续接 Experience Store 写入钩子）。

补充（Dev 可观测）：`/dev/logs` 已提供 `G0ActionReportV1` 与 `ExperienceItem` 的本地检索与导出入口，便于在不引入后端/DB 的前提下完成“证据链可回收”的协作排障与复盘。

## 2. 挂起项 B：微内核（Micro-kernel）+ 插件化技能包

**结论**：方向正确；**不宜在开源首版即做「云端兵工厂动态下载执行」**，否则安全与供应链成本会压过治理主线。

**分层**：

| 阶段 | 内容 | 风险 |
|------|------|------|
| 近期 | 内核保留 G0、HDGP/Ethics、意图解析、Skill 协议；业务连接器 **协议化 + 本地/同仓加载** | 低 |
| 中期 | 外置插件包、manifest、签名、版本门禁 | 中 |
| 远期 | 云端分发 + 强沙箱 + 供应链审计 | 高 |

**与经验存储的关系**：蒸馏出的模板/经验可成为 **插件配置或技能包元数据**；下沉前仍须过审计闸。

## 3. 全域威胁模型：与上述两方案的整合（内核收敛，边缘开放）

### 3.1 为何在开源基座阶段仍需要「威胁模型」

- 开源面最易被滥用；**没有威胁定义，HDGP 审计就缺少「防什么」的基准**。
- 威胁模型支撑：**提示词注入、逻辑劫持、越权 outbound、审计字段伪造** 等路径的**可解释防御**与**红队剧本**（与架构文档 D5 红队闸一致）。

### 3.2 三层防御与两方案的映射

| 层 | 取舍 | 与经验存储 | 与微内核/插件 |
|----|------|------------|----------------|
| **L1 核心基座（开源 Intdeck）** | 安全 > 自由度；生存级、少配置 | 经验写入走 G0+审计锁；**禁止静默自进化进生产路径** | 仅内核接口与本地插件契约；**不默认远程加载** |
| **L2 审计网关（HDGP）** | 可解释性 > 盲目自动化 | Reflection 产出须带 **威胁/风险标签与理由码**（可对用户展示摘要） | 插件 capabilities 与 **实际执行** 对齐校验 |
| **L3 商业完整态（Intdone）** | 全域自动化、运营级监控 | 与流量/行为/财务只读审计等 **全域模型** 联动 | 可选商业插件与托管策略 |

### 3.3 工程取舍（文档化 + 影子模式）

- **威胁模型文档化**：开源随包提供《HDGP / Intdeck 威胁模型白皮书》（攻击面、信任边界、数据流）；代码侧实现 **生存级硬闸**，复杂策略可渐进。
- **Shadow Mode**：主路径低延迟；**异步审计**发现重大问题时 **事后处置 + 下次执行阻断**；须明确 **哪些类别不允许纯异步**（例如不可逆 outbound、资金相关）必须同步阻断。

### 3.4 新增安全功能的判别标准（与两方案共用）

1. 是否直接保护 **三公理 / 生存级安全**？→ 进内核，必要时复杂。  
2. 是否仅防 **特定业务风险**（如爬虫封禁）？→ **插件 / 可选模块**。  
3. 是否增加 **用户认知负担**？→ 默认隐藏在 HDGP/日志，**出事或可审计时再 surfaced**。

## 4. 综合一句话（产品叙事）

**开源 Intdeck** = 带 **ABS 的底盘**（G0 + HDGP + 最小威胁基准 + 可审计经验写入）；**全域威胁模型与全自动运营安全** 放在 **Intdone 商业完整态** 与 **可选插件/托管层**，既保住行业标准叙事，又为商业化留护城河。
